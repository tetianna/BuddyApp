1. Four layers

The framework is not one program. It is four kinds of instruction that Cursor loads, plus tools that reach Jira, GitHub, and the browser.

RulesAlways in the room, or loaded for a task. They set the law. The QA orchestrator is a rule, not an agent file.
SkillsStep-by-step playbooks. An agent reads a skill and follows it. A skill does not run by itself.
AgentsSpecialist workers the parent can start. They take a handoff, do one job, and report back.
HooksAutomatic gates. They run before a file write. They can block an edit. They do not plan work.
You or GitHub ActionsStart a chat, or run the Test Generation workflow
→
Parent agent + rulesConstitution, ESL chat, Playwright style, orchestrator
→
Skills (playbooks)How to analyze, heal, triage, report
→
Specialist agentstest-writer · triage · bug-reporter
MCP + terminalJira, Confluence, GitHub, Playwright browser, npx playwright test
→
Hooks on WriteBlock weak assertions and forbidden patterns
→
Disk artifactsfeatures/ · tests/ · pages/ · pull requests · Jira bugs
The important split. Skills tell someone how. Agents are who does a bounded job. Hooks are a lock on the door. The orchestrator is the parent Cursor session following qa-orchestrator.mdc. There is no .cursor/agents/orchestrator.md file.

3. How they talk

Nothing in this framework calls another piece with an API. Communication is: a parent prompt, a skill file the agent reads, a file on disk, a pull request comment, or a Jira ticket. Hooks speak only by allowing or denying a write.

Channels

Channel What it is Example
Parent prompt The orchestrator (or you) starts a specialist and passes one job. “Here is features/AQPBT-15.feature.md. Write the spec.”
Skill file The worker opens SKILL.md and follows the steps. The skill is not a subprocess. triage applies ci-failure-triage.
Disk artifact The next worker reads a file the last worker wrote. Plan in features/ → spec in tests/.
Handoff text The specialist returns a structured report to the parent. It does not keep going. triage: “Classification: drift. File: pages/….”
MCP / CLI Talk to systems outside the repo. Atlassian MCP for Jira. gh for runs and pull requests. Playwright MCP for live UI.
Hook JSON Before Write or StrReplace, a script returns allow or deny. “Blocked: test assertions weakened…”
GitHub Actions prompt CI starts Cursor CLI agent -p with the orchestrator instructions pasted in. Test Generation workflow, backlog mode.

4. Rules

Rules sit in .cursor/rules/. They shape every answer. Skills and agents must still obey them.

Always on

constitution.mdc

The law for this repo. Must / Should / Won’t tables. Role locators, web-first expect, storage-state login, unique data, one tag per test. Forbids XPath, waitForTimeout, hardcoded secrets, the any type, weakened assertions, healing a real product bug, tags on describe, and a classic BasePage.

Also lists every skill and agent, and the Audit → Proposal → Edit gate for non-trivial work. Confidence under 5: stop. 5–7: wait for you. 8+: proceed and cite evidence. Never invent routes, labels, or env names.

Always on

esl-communication.mdc

How the agent talks to you in chat, tables, and pull request text: short sentences, common words, full phrase before a short form. Does not change code comments or variable names.

When editing tests/

playwright-conventions.mdc

Day-to-day how-to for specs: locators, waiting, page objects, auth, data, tags, factories, API setup, mocking, accessibility, assertions, anti-flake. Hard stops match the constitution. Applied by glob tests/**.

On demand

qa-orchestrator.mdc

The coordinator. Plans and delegates. Never writes test code and never files bugs itself. Reads the ticket (and Confluence). Produces the plan. Sends work to test-writer, triage, and bug-reporter. Caps: 3 delegations, 2 identical failing re-runs, 5 heals. Always triage before heal. Mandatory eval-report before Done when a trigger fired.

5. Agents

Three specialists in .cursor/agents/. Cursor can start them as subagents. The parent must give them a finished input. They return a result. They do not run the whole pipeline alone.

6. Skills

Ten playbooks in .cursor/skills/. Who uses them: the orchestrator, a specialist, or you in chat. Each skill has a clear output path.

Plan · with ticket

jira-ticket-analyzer

Turns a Jira ticket’s acceptance criteria into reviewable Gherkin. Used whenever you name a ticket like AQPBT-15 and ask for a plan — even if you do not say “Gherkin”.

Who
Orchestrator (first step with a ticket). You in chat.
Reads
Atlassian MCP: full Jira issue (every acceptance criterion). Linked Confluence page in space AQPBT.
Writes
features/<ticket-key>.feature.md
Does
One Feature per ticket. Every acceptance criterion → at least one Scenario. Adds negative and edge cases. Real UI strings, not placeholders. Ends with an “Ambiguities and gaps” comment.
Stops
After the feature file, unless you ask for Playwright next. Does not invent acceptance criteria to match the live app.
Plan · no ticket

explore-and-generate

Finds one untested user flow by comparing live UI to existing specs. Ticket-less only. If a ticket exists, use jira-ticket-analyzer instead.

Who
Orchestrator (no-ticket path). You in chat.
Reads
tests/, pages/, live app via Playwright MCP (browser_navigate + browser_snapshot only).
Writes
features/explore-<page>-<flow>.feature.md
Does
Map coverage → crawl page (read-only) → list flows → pick one gap → two Gherkin scenarios (happy + edge) → locator hints for test-writer.
Won’t
Write or run specs. Submit forms that persist data. Take screenshots. Process more than one flow per run.
Diagnose

ci-failure-triage

Turns a red continuous integration (CI) run or local failure into one classification. The triage agent must apply this skill.

Who
triage agent. Orchestrator on red. You when a build fails.
Reads
GitHub MCP or gh logs and playwright-report artifact; or local test-results/. Spec, page object, Gherkin, Confluence. Not BuddyTime source — it is not in this repo.
Writes
A pull request comment, or the same markdown block back to the parent. No code edits.
Labels
drift → later self-heal. real app bug → later bug-reporter. ambiguous → stop and ask you.
Repair locators

self-heal

Fixes one broken locator after triage said drift. Specs and assertions stay the same.

Who
Orchestrator after a drift label. Not used for real product bugs.
Reads
Error, trace (read-only on tests/), live UI snapshot at the failing step.
Writes
One locator in pages/ (or pages/components/). Branch heal/<short-description>. Pull request, not merged.
Verify
Re-run the same failing test. Must pass with zero changes under tests/.
Stops
If an assertion must change; if the same locator error remains; if a new failure looks like a product bug; if the fail is flake/timeout without a label change. Max 5 heals per red run (orchestrator cap).
File a defect

jira-bug-reporter

Turns a confirmed product defect into a Jira draft, then a ticket after you approve.

Who
bug-reporter agent. Never from self-heal. Never for drift.
Reads
Failure, artifacts, Gherkin, live app. Searches AQPBT for duplicates first.
Writes
Chat draft (always). Jira bug + link to the story (only after you say yes). No repo files.
Won’t
File on flake that passes on retry, test bugs, missing env, or behavior already marked as an ambiguity in the feature file.
While writing tests

pom-conventions

Page Object Model rules. Specs assert. pages/ locate and act. No inline locators in tests. Path hint: tests/**, pages/**.

Who
test-writer on every spec. Orchestrator checks that generated page objects match.
Writes
Nothing by itself. Constrains how test-writer writes classes under pages/.
Inventory
Lists every BuddyTime page object and component that exists today (landing, login, dashboard, birthdays, communities, and so on).
While writing tests

api-cleanup

Every test that creates a record must track it so teardown can delete it. Shared BuddyTime env must not fill up with leftover parties.

Who
test-writer whenever a spec creates data.
Writes
Nothing by itself. Tells the spec to import fixtures/cleanup.fixture and call trackRecord.
Runtime
UI creates of birthday events are auto-tracked on POST /api/v1/events → 201. Teardown: support/global-teardown.ts and support/cleanup-reporter.ts.
Types today
Only birthday-event. New types need RecordType + api-client + this skill in the same change.
Close the session

eval-report

Refreshes suite reliability numbers in eval-report.md. Report only. No tickets, no test edits. Cursor has no built-in telemetry — this skill says how to count by hand.

Who
Orchestrator before Done, if a trigger fired. You when you ask for suite health.
Triggers
Heal pull request or red-run triage; generation pull request; file missing or older than 14 days.
Writes
eval-report.md at repo root — or replies eval: skipped — no trigger.
Metrics
Flake rate, heal success, generation-gate pass, ask versus guess. Missing data → write “insufficient data”, never guess.
Human exploration

exploratory-charter

Empty session charter + findings table. You supply risks and observations. The agent does not invent them.

Who
You, when you want a time-boxed explore before or after clicking the app.
Needs
Feature name and risk. If either is missing, stop and ask.
Writes
charters/<feature-slug>.md only.
Won’t
Write specs, file bugs, run Playwright, or crawl for coverage gaps (that is explore-and-generate).
Manual cleanup

test-data-reset

Deletes only records listed in the tracker after a run stopped early. Flag disable-model-invocation: true — the agent must not start this on its own.

Who
You, when you explicitly ask to reset leftover test data.
Reads
.test-artifacts/created-records.jsonl
Runs

7. Hooks

Hooks are the only piece that can stop an edit without asking. Config: .cursor/hooks.json. Event: preToolUse. Matcher: Write|StrReplace. Both are failClosed: true — if the script crashes, the edit is blocked.

Gate

guard-test-assertions.py

Watches spec files under tests/ (.spec.ts, .test.ts, and JS/JSX twins).

Counts active expect( calls. Ignores commented lines. If the new file has fewer expects than the old file, the write is denied.

Message: do not delete or comment out assertions to make tests pass. Fix the app, the locator, or the test data.

Gate

guard-constitution.py

Watches tests/ and pages/ TypeScript/JavaScript files.

Blocks an edit that adds a forbidden pattern: .waitForTimeout(, XPath locator('//…'), the any type, a hardcoded email in .fill(), a hardcoded password/secret/token, or a tag on test.describe().

On spec files it also blocks a drop in expect( count (second line of defense).

How a hook talks. Cursor sends JSON on standard input (tool name + proposed contents). The script prints JSON: permission: allow or permission: deny plus a message to you and to the agent. The agent sees the deny and must change the plan. It cannot “heal” by deleting the failing expect.
What hooks do not do. They do not start workflows. They do not classify red runs. They do not know Jira. Shell wrappers (.sh) exist so the same Python can run on Unix. On this Windows machine, hooks.json calls python .cursor/hooks/…py directly.

9. Main workflow — ticket to tests

This is the happy path when you (or backlog mode) have a Jira key. The orchestrator plans. Specialists write. Hooks watch the writes.

1ReadOrchestrator + Atlassian MCP. Jira issue and linked Confluence page.
2PlanSkill jira-ticket-analyzer. File: features/AQPBT-n.feature.md.
3WriteAgent test-writer. Spec in tests/, actions in pages/. Hooks may deny.
4Runtest-writer runs the spec. Orchestrator may run a wider slice.
5HandoffGreen → pull request. Red → Heal on red (section 11). Then eval-report if triggered.
You
Give a ticket key. Later approve the pull request (and any bug). You merge. The agent never merges.
Orchestrator
Reads the ticket. Runs the analyzer skill. Saves the plan. Starts test-writer. If red, starts triage. Routes heal vs bug. Asks for eval-report at the end.
jira-ticket-analyzer
Playbook only. Writes Gherkin to features/. Stops for review unless you already asked for implementation.
test-writer
Reads the plan + existing page objects. Follows pom-conventions and api-cleanup. Writes spec and POM methods. Runs once. Reports path + result.
Hooks
On every Write/StrReplace to tests or pages: block weaker expects and constitution violations.
Disk
features/AQPBT-n.feature.md → tests/aqpbt-n-….spec.ts → pages/….page.ts. Optional pull request branch tests/<key>-<slug> in backlog mode.

10. Main workflow — no ticket

Same parent, different first skill. Discovery is read-only. Automation still goes through test-writer after you accept the plan.

  1. 1
    Orchestrator applies explore-and-generate. Maps what specs already cover. Opens the live page with Playwright MCP. No screenshots. No submits that save data.
  2. 2
    One gap is chosen. Two Gherkin scenarios. Locator hints. Suggested spec path. Suggested Jira story text (not filed here).
  3. 3
    File: features/explore-<page>-<flow>.feature.md. You review.
  4. 4
    Delegate test-writer with that plan — same as the ticket path from step 3 onward.
Do not mix paths. A ticket with acceptance criteria always uses jira-ticket-analyzer. explore-and-generate is only when there is no ticket.

11. Main workflow — heal on red

Always classify first. Healing a real product bug is forbidden. The constitution, orchestrator, self-heal skill, and bug-reporter skill all say the same thing.

Red runCI or local spec
→
OrchestratorStarts triage. Does not patch yet.
→
triage + ci-failure-triageOne label only
Driftself-heal: one locator in pages/. Re-run same test. Pull request heal/… Assertions unchanged.
Real app bugbug-reporter + jira-bug-reporter. Draft in chat. File in AQPBT after you approve. Link the story. No heal.
AmbiguousStop. List unknowns. Ask you. No more heal loops.
triage
Read-only. Pulls logs and the report artifact. Reads spec, POM, Gherkin, Confluence. Returns classification + file:line + suggested next step.
self-heal
Only after drift. Snapshot the live control. Patch POM. Hooks still apply. Open pull request. Do not merge. Do not file Jira.
bug-reporter
Only after real app bug. Re-run once (pass on retry → flake, do not file). Search duplicates. Draft. Wait. File. Return the key.
Hooks
If someone tries to go green by deleting expect(, the write is denied. That is how “never weaken assertions” is enforced, not only written.
Hard stops. Same locator error after heal attempts → stop. Green only if an assertion changes → stop (not drift). Same spec failed identically twice → escalate. Never merge, close a ticket, or close a pull request without you.

12. Main workflow — backlog mode

An outer runner processes one Jira ticket per run. The runner is GitHub Actions (Test Generation) or a local/headless agent -p. The inner loop is the same ticket path as section 9.

  1. 1
    Queue. Project JIRA_PROJECT_KEY (AQPBT). Status In QA. Label tests-generated is absent. At most one issue. Empty queue → stop, no pull request.
  2. 2
    Manual dispatch override. If you pass jira_key into the workflow, process only that issue. If it is missing, wrong project, or already labeled, stop.
  3. 3
    Per ticket: analyzer → commit the feature file → test-writer → run the new spec → heal on red (triage first).
  4. 4
    Success output: one pull request, ticket linked in the body, Gherkin path named, branch tests/<key>-<slug>. If the spec is green, add label tests-generated.
  5. 5
    Failure output: repeated identical failure. Pull request may stay open. Do not add tests-generated. Escalate.
  6. 6
    Done: eval-report skill. Never merge, never transition Jira, never close the pull request.
Where this lives. Policy: .cursor/rules/qa-orchestrator.mdc (Backlog mode). Automation: .github/workflows/test-generation.yml (cron Monday–Friday 14:00 UTC, concurrency group test-generation). Write scope in that prompt: features/, tests/, pages/, test-data/, eval-report.md.

13. Other workflows

Charter

Exploratory session

Who: you + exploratory-charter skill. Not the orchestrator loop.

Where: charters/<slug>.md.

Flow: you name feature + risk → agent fills only non-judgment fields → you explore and write findings → if a real bug is confirmed, then bug-reporter (separate).

Metrics

Eval report

Who: orchestrator at session close, or you.

Where: eval-report.md.

Flow: check triggers → gh run list / pull request history / transcripts → fill the four metrics or “insufficient data” → one reliability risk + one next action.

Ops

Reset leftover data

Who: only you, explicit ask.

Where: tracker file + api-client deletes.

Flow: dry-run list → you confirm → script deletes tracker rows only (today: birthday-event). 404 on delete counts as cleaned, not as flake.

CI tests

Playwright GitHub job

Who: GitHub Actions, not an agent.

Where: playwright.yml.

Flow: checkout → Node 20 → npm ci → Chromium → npx playwright test → upload playwright-report/. If this job is red, a person or the orchestrator starts triage.

14. Human gates and loop limits

The framework is allowed to plan, write tests, open pull requests, and draft bugs. A person still owns merge, filing, and “this is a real defect.”

You must approve

  • Every merge
  • Every Jira bug before it is created
  • test-data-reset after the dry-run
  • Overwriting an existing charter file
  • Work with confidence 5–7 (unknowns listed)
  • Closing a ticket or a pull request

Automatic stops

  • At most 3 delegations per task (heal retries extra)
  • Never re-run the same failing spec more than twice
  • At most 5 heals per red run
  • Identical failure twice → escalate, no tests-generated
  • Confidence < 5 → stop and ask
  • Hooks deny a write that weakens expects or adds a Won’t pattern
Audit → Proposal → Edit (constitution, behavioral, not a hook). Before a non-trivial change the parent must list scope, confidence 1–10, why, and unknowns — then wait unless confidence is 8 or higher. Trivial = a one-line fix with obvious intent.

15. One full walk, from ticket to done

Example: story AQPBT-15 (profile details). This is the same travel the orchestrator is built for.

  1. 1
    You or Test Generation pass AQPBT-15 (or the queue picks it: In QA, no tests-generated).
  2. 2
    Orchestrator loads constitution + qa-orchestrator. Reads the Jira issue and the Confluence page through Atlassian MCP.
  3. 3
    jira-ticket-analyzer writes features/AQPBT-15.feature.md with AC-mapped scenarios, negatives, edges, and an ambiguity footer. Disk is now the handoff.
  4. 4
    test-writer reads that file and pages/profile.page.ts. Follows pom-conventions and api-cleanup. Writes tests/aqpbt-15-profile-your-details.spec.ts. Each Write hits both hooks.
  5. 5
    test-writer runs npx playwright test on that spec and reports pass or fail. Never claims success without this run.
  6. 6
    If red: triage + ci-failure-triage. Drift → self-heal patches the page object, re-runs the same test, opens heal/…. Real bug → bug-reporter drafts AQPBT bug, waits for you. Ambiguous → stop.
  7. 7
    If green: open a pull request (backlog: branch tests/aqpbt-15-…, body links the feature file and the Jira key). Add label tests-generated only when the spec is green.
  8. 8
    eval-report if a generation or heal trigger fired. Update eval-report.md or note eval: skipped.
  9. 9
    You review and merge. The framework stops here on purpose.
Remember the split. Rules set the law. Skills are the recipes. Agents are the cooks for one dish. Hooks are the smoke alarm. The orchestrator is the head chef who never plates the food — it delegates, then checks the result.
